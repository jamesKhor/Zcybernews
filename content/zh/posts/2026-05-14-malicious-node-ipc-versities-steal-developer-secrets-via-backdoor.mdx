## 执行摘要

Socket 和 StepSecurity 的研究人员发现了广泛使用的 npm 包 `node-ipc` 的三个版本中存在恶意代码——版本 9.1.6、9.2.3 和 12.0.1——这些版本充当窃取凭证的后门。这些被破坏的包将 SSH 私钥、AWS 和 GitHub 凭证、环境变量以及其他敏感的开发者机密信息泄露到远程服务器。截至发稿时，node-ipc 的维护者尚未发表公开声明，恶意版本仍然可以在 npm 上获取。Socket 和 StepSecurity 在 2026 年 5 月 13 日报告了这些发现。

## 技术分析

恶意负载嵌入在包分发中的一个名为 `ssl.js` 的文件里。根据 Socket 的分析，代码通过在 `package.json` 中定义的 `postinstall` 脚本在包安装期间执行。执行后，`ssl.js` 收集一系列广泛的文件和环境变量：

- 从 `~/.ssh/id_rsa`、`~/.ssh/id_dsa` 和 `~/.ssh/id_ecdsa` 收集 SSH 私钥
- 从 `~/.aws/credentials` 收集 AWS 凭证
- 从 `~/.config/gh/hosts.yml` 收集 GitHub 令牌
- 从当前 shell 会话收集环境变量
- 收集项目目录中的 `.env` 文件

被盗数据被合并成一个单一的有效载荷，并通过 HTTP POST 请求传输到一个硬编码的 IP 地址（StepSecurity 报告为 `45.33.32.156`）。外泄使用自定义 User-Agent 字符串以融入合法流量。Socket 指出，恶意代码使用字符串编码和条件执行检查进行混淆，这些检查仅在非 Windows 系统上触发，表明攻击者针对的是运行 macOS 或 Linux 的开发者工作站。

StepSecurity 的独立分析确认了相同的三个版本，并补充说后门还试图读取可能包含 npm 认证令牌的 `~/.npmrc` 文件。研究人员强调，恶意版本是由合法包维护者的账户发布的，这表明要么 npm 令牌被泄露，要么直接接管了账户。维护者尚未对评论请求作出回应。

受影响的三个版本在 2026 年 5 月 12-13 日的 48 小时内发布。Node-ipc 是一个流行的进程间通信库，被数千个项目使用，包括几个高知名度的框架。截至本文撰写时，npm 注册表似乎没有标记或移除这些包。

## 缓解措施与建议

安装了这三个恶意版本的开发者应立即：

1. 移除受影响的包，并审计其依赖树以查找传递性包含。
2. 轮换所有 SSH 密钥、AWS 凭证、GitHub 令牌以及可能存在于受影响机器上的任何其他机密。
3. 审查 shell 历史记录和环境变量转储，寻找外泄的迹象。
4. 监控云服务日志，寻找来自外泄 IP（`45.33.32.156`）的未经授权的访问。

组织应强制执行 npm 包完整性验证，使用锁文件，并考虑使用像 Socket 或 npm audit 这样的工具来检测恶意包。固定依赖版本并避免对关键库自动进行次要/补丁更新可以减少暴露于这类供应链攻击的风险。
