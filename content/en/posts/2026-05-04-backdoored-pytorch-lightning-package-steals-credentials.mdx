## Executive Summary

A malicious version of the PyTorch Lightning package published on the Python Package Index (PyPI) delivers a credential-stealing payload targeting browsers, environment files, and cloud services. The rogue package, version 2.5.0-post1, was uploaded on April 30, 2026, according to BleepingComputer. It impersonates the legitimate PyTorch Lightning library, a popular framework for deep learning research and production ML pipelines. The backdoored package exfiltrates stored credentials from Chrome, Firefox, and Edge browsers, as well as tokens from environment variables and cloud SDK configuration files.

## Technical Analysis

The malicious package uses a typosquatting approach: the legitimate package is `pytorch-lightning` (with a hyphen), while the rogue package uses `pytorch_lightning` (with an underscore). This subtle difference can bypass visual inspection in pip install commands or requirements files. Upon installation, the package executes a Python script that collects:

- Browser cookies and saved credentials from Chromium-based browsers (Chrome, Edge, Brave) and Firefox
- Environment variables containing API keys, database passwords, and cloud provider tokens
- AWS, GCP, and Azure SDK configuration files (`~/.aws/credentials`, `~/.config/gcloud`, `~/.azure/azureProfile.json`)

The stolen data is then exfiltrated to a remote server via an HTTP POST request. The payload does not persist beyond the installation step, meaning it only executes during `pip install`. However, any credentials harvested at that point are immediately compromised.

## Mitigations & Recommendations

Organizations using PyTorch Lightning in CI/CD pipelines or production environments should immediately audit their dependency trees for the malicious version. The legitimate PyTorch Lightning package is published under the name `pytorch-lightning` (hyphenated). Defenders should verify package hashes against the official PyPI releases and consider pinning versions to known-good hashes. For ML teams, scanning `requirements.txt` and `pyproject.toml` files for underscore variations of known packages can catch typosquatting attacks. Additionally, running `pip install` in isolated environments (containers or virtual machines) with network egress restrictions can limit the blast radius of such supply-chain attacks.
