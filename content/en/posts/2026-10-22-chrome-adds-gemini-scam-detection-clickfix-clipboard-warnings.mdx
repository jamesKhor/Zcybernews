## Executive Summary

Google has moved Chrome's scam detection from an on-device Gemini model to a more capable server-side model and added a clipboard check that inspects commands copied from ClickFix lures before the user pastes them into a terminal. Both capabilities ship under Enhanced Protection in Safe Browsing, the opt-in tier Google says makes users ten times safer against phishing and social engineering than Standard Protection. The practical takeaway for defenders: the two highest-value additions — server-side Gemini analysis and ClickFix command interception — are unavailable to users on Standard Protection, so enterprise policy that leaves Enhanced Protection off will not benefit from either.

## Technical Analysis

Chrome previously ran an on-device Gemini model to detect tech support scams. Google is now shifting that workload to a server-side model for Enhanced Protection users, which the company describes as more powerful. According to Google, the model evaluates signals including the brand represented on a page, the page's apparent intent, and the likelihood that the page is a scam; Safe Browsing then combines that assessment with domain reputation and other security signals.

Google told BleepingComputer that Chrome limits data exposure by analyzing page text only when a site exhibits high-confidence scam indicators, and that any page content sent off-device is processed ephemerally — never logged, retained, or used to train models. That claim is Google's own characterization; no independent audit of the ephemeral-processing pipeline was cited in the source material.

The ClickFix feature targets a technique in which attackers trick users into copying and pasting malicious PowerShell or Command Prompt commands into their own machines, bypassing conventional security controls. When Chrome suspects a copied payload is a ClickFix script, it strips personally identifiable information from the clipboard content and submits the remainder to Safe Browsing for analysis. If the payload comes back dangerous, Chrome displays a warning before the user proceeds. The source material does not specify which PII fields are stripped, how the classifier decides a clipboard payload is "suspicious" in the first place, or whether the warning is bypassable.

Chrome is also introducing a new "suspicious site" warning tier for pages that exhibit deceptive patterns but do not meet the confidence threshold for the existing full-page red interstitial. Google's stated rationale is that a tailored warning UI lets it safely expand coverage and surface a higher volume of protective warnings without over-blocking. The company did not publish the deceptive-pattern signals or the confidence thresholds that separate a suspicious-site warning from a full red warning.

## Mitigations & Recommendations

Because both new capabilities are gated behind Enhanced Protection, the first action for defenders is to confirm which Safe Browsing tier their managed fleet is on and whether policy permits Enhanced Protection given its data-sharing posture. Organizations that have deliberately disabled Enhanced Protection for privacy reasons should treat the Gemini scam model and the ClickFix clipboard check as unavailable and compensate elsewhere — for example, by blocking or alerting on PowerShell and Command Prompt execution spawned from browser processes, and by monitoring clipboard-to-shell chains on endpoints.

For users on Enhanced Protection, no configuration change is required beyond ensuring the tier is enabled. Security teams should also expect ClickFix operators to adapt: the clipboard check only fires when Chrome classifies a payload as suspicious, so obfuscated or split commands that evade the classifier would still reach the shell. Detection engineering should not assume browser-side interception replaces endpoint command-line telemetry.
