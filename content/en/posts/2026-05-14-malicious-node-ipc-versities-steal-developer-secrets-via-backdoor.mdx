## Executive Summary

Researchers at Socket and StepSecurity have identified malicious code in three versions of the widely used npm package `node-ipc` — versions 9.1.6, 9.2.3, and 12.0.1 — that functions as a credential-stealing backdoor. The compromised packages exfiltrate SSH private keys, AWS and GitHub credentials, environment variables, and other sensitive developer secrets to a remote server. The maintainer of node-ipc has not yet issued a public statement, and the malicious versions remain available on npm as of publication. Socket and StepSecurity reported the findings on May 13, 2026.

## Technical Analysis

The malicious payload is embedded in a file named `ssl.js` within the package distribution. According to Socket's analysis, the code executes during package installation via a `postinstall` script defined in `package.json`. Upon execution, `ssl.js` collects a broad set of files and environment variables:

- SSH private keys from `~/.ssh/id_rsa`, `~/.ssh/id_dsa`, and `~/.ssh/id_ecdsa`
- AWS credentials from `~/.aws/credentials`
- GitHub tokens from `~/.config/gh/hosts.yml`
- Environment variables from the current shell session
- `.env` files in the project directory

The stolen data is concatenated into a single payload and transmitted via an HTTP POST request to a hardcoded IP address (reported as `45.33.32.156` by StepSecurity). The exfiltration uses a custom User-Agent string to blend in with legitimate traffic. Socket noted that the malicious code is obfuscated using string encoding and conditional execution checks that only trigger on non-Windows systems, suggesting the attacker targeted developer workstations running macOS or Linux.

StepSecurity's independent analysis confirmed the same three versions and added that the backdoor also attempts to read `~/.npmrc` files, which can contain npm authentication tokens. The researchers emphasized that the malicious versions were published by the legitimate package maintainer's account, indicating either a compromised npm token or a direct account takeover. The maintainer has not responded to requests for comment.

The three affected versions were published within a 48-hour window on May 12-13, 2026. Node-ipc is a popular inter-process communication library used in thousands of projects, including several high-profile frameworks. The npm registry does not appear to have flagged or removed the packages as of this writing.

## Mitigations & Recommendations

Developers who have installed any of the three malicious versions should immediately:

1. Remove the affected package and audit their dependency tree for transitive inclusions.
2. Rotate all SSH keys, AWS credentials, GitHub tokens, and any other secrets that may have been present on the affected machine.
3. Review shell history and environment variable dumps for signs of exfiltration.
4. Monitor cloud service logs for unauthorized access originating from the exfiltration IP (`45.33.32.156`).

Organizations should enforce npm package integrity verification using lockfiles and consider using tools like Socket or npm audit to detect malicious packages. Pinning dependency versions and avoiding automatic minor/patch updates for critical libraries can reduce exposure to this class of supply-chain attack.
